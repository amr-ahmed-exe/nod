# Nod-RS — Agent Rules

> Every AI agent working on this codebase MUST read and follow these rules.

## Project Context

This is a **Rust rewrite** of the Nod desktop application (originally Electron/TypeScript).
The goal: **pixel-identical UX** with the original Nod app, but running natively via Rust (iced 0.14 + wgpu), making it lighter and faster than Electron.

The original source is at `../src-ts/` and the original compiled app assets are at `../backup-installed/`.

---

## ⛔ NEVER

1. **Never invent new UI** — do not create layouts, colors, spacing, animations, or interactions that aren't in the original app. When in doubt, check `../src-ts/src/web/`.
2. **Never hard-code colors** — all colors come from `palette.rs` via `theme::palette()`.
3. **Never use `unwrap()` or `expect()` in runtime paths** — use `Result`/`Option` chaining or return errors with descriptive messages.
4. **Never duplicate types** — if a type exists in one file, import it; do not redefine it.
5. **Never edit `icon_data.rs` manually** — it is auto-generated SVG path data.

## ✅ ALWAYS

1. **Always run `cargo clippy -- -W clippy::all`** before considering a task done. Zero warnings.
2. **Always run `cargo build --release`** to verify the build compiles.
3. **Always keep lines ≤ 100 characters** — break long chains across multiple lines.
4. **Always add doc-comments (`///`)** to new public types and functions.
5. **Always use `Cow<'_, str>` or `&str`** instead of `String` clones where the data is read-only.
6. **Always keep `palettes.json` and `palette.rs` in sync** when adding/changing colors.
7. **Always test theme switching** (AMOLED ↔ Light ↔ Mocha) after any visual change.

## Architecture

```
src/
  main.rs          → iced::application entry point ONLY
  ui.rs            → (currently) view + update + state — BEING SPLIT
  model.rs         → API response types (serde Deserialize)
  api.rs           → reqwest HTTP client
  bots.rs          → Bot struct, persistence, CRUD
  computer.rs      → Spawns nod-host.mjs, reads JSON events
  theme.rs         → Appearance enum, global state, title bar colors
  palette.rs       → Static color palettes (AMOLED, LIGHT, MOCHA)
  styles.rs        → iced button/container/input style functions
  icons.rs         → Icon enum → SVG Element
  icon_data.rs     → Raw SVG path strings (auto-generated)
  secrets.rs       → Windows DPAPI seal/open
host/
  nod-host.mjs     → Node.js bridge to Nod's engine
  engine-shim.mjs  → Electron IPC polyfill
legacy/
  engine.rs, host.rs → Old approach, NOT compiled, kept for reference
```

## Error Messages

- **User-facing:** `"Nod could not {verb}: {detail}"` or `"Nod's {component} {what happened}."`
- **Internal/logs:** Descriptive with context, using `format!`.
